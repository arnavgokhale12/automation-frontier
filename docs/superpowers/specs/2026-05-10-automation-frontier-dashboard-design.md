# Automation Frontier Dashboard — Design Spec

**Date:** 2026-05-10
**Status:** Approved

---

## Overview

A public-facing dashboard that answers: *"Where is automation technically possible, but blocked by regulation, trust, physical-world friction, capital, or human taste?"*

Three sections — Human Bottleneck Index, Automation Sandbox, Civilization Patch Notes — presented as a unified tool with a persistent sidebar. Deployed as a standalone app (own domain) that also links back to the author's portfolio.

**Primary audience:** Tech/AI crowd — assumes familiarity with AI capabilities, focuses on deployment gaps and structural bottlenecks.

---

## Stack

- **Framework:** Next.js 15 (App Router), TypeScript
- **Styling:** Tailwind CSS — Terminal/Data Lab aesthetic: dark background (`#0a0a0f`), monospace accents, neon highlights (`#00ff88`, `#00bfff`, `#ff6b35`)
- **AI:** Vercel AI SDK (`streamObject`) → Anthropic Claude API
- **Deployment:** Vercel (free tier, serverless functions for Claude API calls)
- **Content:** MDX for Patch Notes, structured JSON for index/sandbox data

**Environment variables:** `ONET_USERNAME`, `ONET_PASSWORD`, `ANTHROPIC_API_KEY`
(BLS Public Data API requires no key)

## Architecture

### Data Strategy: Build-time Static

All industry and occupation data is fetched once by an ingestion script and committed to the repo as JSON. Pages are statically generated at build time. The Claude API is called at runtime only for Sandbox fallbacks. No database, no persistent server.

```
automation-frontier/
├── app/
│   ├── layout.tsx              # Shell with persistent sidebar
│   ├── page.tsx                # Redirect to /index
│   ├── index/page.tsx          # Human Bottleneck Index
│   ├── sandbox/page.tsx        # Automation Sandbox
│   ├── sandbox/actions.ts      # Server action → Claude API
│   ├── patch-notes/page.tsx    # Patch Notes list
│   ├── patch-notes/[slug]/     # Individual patch note
│   └── patch-notes/feed.xml/   # RSS feed route
├── components/
│   ├── Sidebar.tsx
│   ├── BottleneckTable.tsx
│   ├── RadarChart.tsx
│   └── PatchNote.tsx
├── content/patch-notes/        # MDX files (e.g. 2026-05.mdx)
├── data/
│   ├── industries.json         # Generated by ingest.ts
│   ├── occupations.json        # Generated by ingest.ts
│   └── sandbox-prebuilt.json   # Hand-authored job breakdowns
└── scripts/
    ├── ingest.ts               # O*NET + BLS ingestion script
    └── manual-overrides.json   # Hand-curated regulation + trust scores
```

### Layout Shell

Persistent left sidebar (~220px) containing:
- App name / logo
- Section navigation: Index, Sandbox, Patch Notes
- Active filter chips (visible when filters are applied in Index)
- Link back to author's portfolio

Sidebar collapses to icon-only on mobile. Main content area takes remaining width.

## Section 1: Human Bottleneck Index (`/index`)

Sortable, filterable table of industry sectors.

**Columns:**
| Column | Source | Type |
|---|---|---|
| Industry | Manual label | string |
| AI Capability | O*NET tech skills score | 1–5 |
| Physical Friction | O*NET work activity scores | 1–5 |
| Regulation | Manual override | 1–5 |
| Trust Need | Manual override | 1–5 |
| Automation Risk | Composite formula | 1–5 |
| Employment | BLS employment count | number |

**Interactions:**
- Click any column header to sort ascending/descending
- Sidebar filter chips filter by bottleneck type (Regulation, Trust, Physical, Capital) — multi-select
- Click a row to expand an inline detail panel showing top 5 occupations in that industry with their O*NET automation exposure scores

**Data sources:** O*NET Web Services (work activities, technology skills) + BLS Public Data API (employment counts) + `scripts/manual-overrides.json` (regulation, trust scores)

---

## Section 2: Automation Sandbox (`/sandbox`)

Interactive job analyzer.

**UX flow:**
1. Free-text search input with O*NET occupation autocomplete (client-side filter over `data/occupations.json`)
2. User selects a job → component breakdown renders
3. If job is in `data/sandbox-prebuilt.json`: renders instantly from static data
4. If not: calls server action `analyzeJob(title)` → Claude API → streams back JSON matching the prebuilt schema → radar chart animates as tokens arrive

**Components rendered per job:**
- Radar chart with 7 axes: Knowledge Work, Judgment, Trust, Physical Execution, Legal Liability, Human Preference, Cost to Deploy (each scored 0–100)
- Primary bottleneck label (e.g. "Legal Liability")
- 2–3 sentence editorial summary
- Link to related industry row in the Index

**Prebuilt jobs (~25):** Accountant, Lawyer, Radiologist, Software Engineer, Nurse, Teacher, Therapist, Financial Analyst, Truck Driver, Construction Worker, Chef, Customer Service Rep, Journalist, Paralegal, HR Manager, Pharmacist, Architect, Tax Preparer, Loan Officer, Insurance Adjuster, Recruiter, Data Analyst, Copywriter, Medical Coder, Real Estate Agent

**Claude API prompt:** Structured system prompt instructing Claude to return JSON matching the sandbox schema. Uses `streamObject` from Vercel AI SDK with strict output schema validation.

## Section 3: Civilization Patch Notes (`/patch-notes`)

Editorial commentary layer on top of the dashboard data.

**Format:** MDX files in `content/patch-notes/`, named `YYYY-MM.mdx`. Rendered with a custom `<PatchNote>` component mimicking a game changelog — version header (`Patch v2026.05`), buff/nerf labels, sector tags.

**Frontmatter schema:**
```yaml
version: "2026.05"
date: "2026-05-01"
title: "White-collar labor nerfed"
summary: "AI capability in document-heavy jobs increased, but legal accountability and trust bottlenecks remain unresolved."
tags: ["finance", "legal", "software"]
relatedIndustries: ["software-dev", "financial-services"]
relatedSandboxJobs: ["accountant", "lawyer"]
```

**List page** (`/patch-notes`): Sorted newest-first, shows version, date, title, tags, one-line summary.

**Detail page** (`/patch-notes/[slug]`): Full MDX body with inline links to relevant Index rows and Sandbox jobs.

**RSS feed** (`/patch-notes/feed.xml`): Standard RSS 2.0, generated as a Next.js route handler. Lets readers subscribe.

## Data Model

### `data/industries.json`
```ts
interface Industry {
  id: string                 // "software-dev"
  name: string               // "Software Development"
  aiCapability: number       // 1–5
  physicalFriction: number   // 1–5
  regulation: number         // 1–5, from manual-overrides.json
  trustNeed: number          // 1–5, from manual-overrides.json
  automationRisk: number     // (aiCapability * 0.4) - (regulation * 0.2) - (physicalFriction * 0.2) - (trustNeed * 0.2), clamped 1–5
  bottleneckTypes: string[]  // any dimension scoring ≥ 4: ["regulation", "trust", "physical"]
  blsEmployment: number
  occupationIds: string[]    // O*NET SOC codes
}
```

### `data/occupations.json`
```ts
interface Occupation {
  socCode: string            // "15-1252.00"
  title: string
  industryId: string
  automationExposure: number // O*NET score, normalized 0–100
  workActivities: string[]   // top activity categories
}
```

### `data/sandbox-prebuilt.json`
```ts
interface SandboxEntry {
  title: string
  components: {
    knowledgeWork: number      // 0–100
    judgment: number
    trust: number
    physicalExecution: number
    legalLiability: number
    humanPreference: number
    costToDeploy: number
  }
  summary: string             // 2–3 sentence editorial take
  bottleneck: string          // primary bottleneck label
  industryId: string          // links to Index row
}
```

## Ingestion Script (`scripts/ingest.ts`)

Run with: `npx tsx scripts/ingest.ts`

**Steps:**
1. Fetch O*NET occupation list + work activity scores + technology skills scores via O*NET Web Services REST API
2. Fetch BLS employment counts per SOC code via BLS Public Data API (no key needed)
3. Load `scripts/manual-overrides.json` for regulation + trust scores
4. Normalize all scores to 1–5 scale, compute `automationRisk` composite
5. Group occupations into industries, write `data/industries.json` + `data/occupations.json`

**Run cadence:** Re-run whenever publishing a new Patch Note. Commit updated JSON alongside the MDX file so data and commentary stay in sync in git history.
